Privacy Policy

Effective Date: June 23, 2026

1. Introduction

Promise Model Online ("PMO," "we," "our," or "us") is a self-hosted project management application. This Privacy Policy explains how personal data is collected, used, stored, and disclosed when you use the PMO application. We are committed to compliance with applicable privacy laws, including:

  • PIPEDA (Personal Information Protection and Electronic Documents Act — Canada)
  • GDPR (General Data Protection Regulation — EU)
  • CCPA/CPRA (California Consumer Privacy Act)

2. Data Controller

Because PMO is self-hosted, the organization deploying the software is the data controller. The organization determines the purpose and means of processing personal data. PMO's developers do not collect, store, or have access to any data from deployed instances.

3. Information We Collect

3.1 Account Information

When a user registers through the internal registration form, we collect:

  • Username
  • Email address (verified via email confirmation when SendGrid is configured)
  • Password (hashed, never stored in plaintext)

After registration, users may set a display name within the application.

3.2 User-Generated Content

Data created through normal use of the application:

  • Project names, descriptions, and metadata
  • Promise, Epic, Journey, Flow, and Moment statements and descriptions
  • Stride and iteration planning data
  • Comments, reactions, and @mentions
  • Task assignments and effort estimates

3.3 Technical Data

  • Session cookie: A single authentication cookie (__Host-pmo.session) is set by the backend-for-frontend (BFF). It is HttpOnly, Secure, and SameSite=Lax. It stores no personal data and expires after 8 hours of inactivity.
  • Audit logs: User actions (create, update, delete) are logged with actor identity, timestamp, entity type, and changes for security and compliance. These logs are stored within the deployed database.

3.4 Application Performance Telemetry (Optional)

The deployment may include an optional client-side telemetry module. When enabled, this module collects fully anonymized performance and health metrics:

  • JavaScript heap size (sampled every 60 seconds)
  • DOM node count
  • Count of uncaught runtime errors (error messages only, no stack traces)
  • Count of long-running tasks (>50ms, indicating possible jank)
  • Service worker state (registered / activated / error)
  • Current page route (anonymized — project names and identifiers replaced with placeholders)

The telemetry module explicitly does not collect:

  • User IDs, usernames, email addresses, or any account identifiers
  • IP addresses
  • Cookies or any data stored in cookies
  • Stack traces (which may contain user data or PII)
  • URL query parameters, form data, or any text content from the DOM
  • Project names, task descriptions, comments, or any user-generated content
  • Session tokens or authentication material

The telemetry module respects the Global Privacy Control (GPC) signal. Users may also opt out at any time by adding <meta name="telemetry" content="off"> to the page, which can be configured by the deploying organization. There is no persistent storage, no queuing, and no retry on delivery failure — all data is sent on a best-effort basis via the Beacon API.

3.5 Analytics (Optional)

The deployment may include self-hosted Umami analytics. When configured, Umami collects:

  • Pages viewed and referrer URLs
  • Browser type, operating system, and device type
  • Country-level geography (derived from anonymized IP addresses)

Umami does not use cookies, does not collect personally identifiable information, does not track users across sites, and never shares data with third parties. All analytics data remains on the deployment server.

3.6 Federated Authentication (Optional)

If the deploying organization enables Google OAuth as an external identity provider using OpenID Connect (OAuth 2.1), users may sign in with their Google account. In this flow, PMO receives the user's Google email address and name during first sign-in. PMO does not access any other Google account data. Internal registration with email verification remains available regardless of whether Google OAuth is enabled.

3.7 Email Communications (Optional)

If SendGrid is configured, email addresses may be used for account verification, password resets, invitation notifications, and deadline reminders. Email content is transactional only; PMO does not send marketing emails.

4. How We Use Information

Personal data is used exclusively for:

  • Providing the project management service (creating, displaying, and managing work items)
  • Authenticating users and managing sessions
  • Enabling collaboration features (comments, @mentions, reactions)
  • Sending transactional notifications (if configured)
  • Maintaining audit trails for security and compliance

We do not sell personal data. We do not use personal data for automated decision-making or profiling.

5. Legal Basis for Processing (GDPR)

For users in the European Economic Area, processing is based on:

  • Legitimate interest: Providing the project management service the user or their organization has requested.
  • Consent: Where required (e.g., optional analytics and telemetry, Google OAuth). Consent may be withdrawn at any time.
  • Contractual necessity: Processing required to deliver the service to the deploying organization.

6. Data Storage and Security

All data is stored on servers controlled by the deploying organization. PMO employs:

  • HTTPS encryption for all data in transit
  • Password hashing using industry-standard algorithms
  • OAuth 2.1 and OpenID Connect for authentication
  • Content Security Policy (CSP) blocking all external resource loads
  • Rate limiting to prevent brute-force attacks
  • Docker secrets for all credentials and keys
  • Non-root application containers
  • Cloudflare tunnel for edge security, TLS termination, and DDoS protection

7. Data Retention

Data is retained for as long as the deploying organization maintains the PMO instance. Users may request deletion of their account and associated data at any time. Audit logs may be retained longer for security and legal compliance. The deploying organization is responsible for defining and communicating specific retention policies.

8. Third-Party Dependencies

Telemetry and analytics data are transmitted to the same server. Whether each optional integration is active depends on the deploying organization's configuration:

9. Your Rights

Depending on your jurisdiction, you have the right to:

  • Access: Request a copy of your personal data.
  • Rectification: Correct inaccurate or incomplete data.
  • Erasure: Request deletion of your personal data ("right to be forgotten") through the My Data page at /account/delete or by contacting your administrator.
  • Portability: Receive your data in a structured, machine-readable JSON format via the /api/users/me/export endpoint, accessible through the My Data page at /account/delete.
  • Restriction: Limit how your data is processed.
  • Objection: Object to processing based on legitimate interest.
  • Withdraw consent: Where processing is consent-based (telemetry and analytics may be opted out by the deploying organization).

To exercise these rights, contact the deploying organization's administrator. Requests will be fulfilled within 30 days as required by applicable law.

10. Cookie Policy

PMO uses a single essential session cookie (__Host-pmo.session) for authentication. This cookie:

  • Is HttpOnly (inaccessible to JavaScript)
  • Is Secure (transmitted only over HTTPS)
  • Has SameSite=Lax (sent only with same-site requests)
  • Expires after 8 hours of inactivity
  • Contains no personal data

No tracking cookies, advertising cookies, or third-party cookies are used by PMO. The optional Umami analytics module does not use cookies. The optional telemetry module does not use cookies or persistent storage.

11. International Data Transfers

Because PMO is self-hosted, all data resides on servers under the deploying organization's control. The deploying organization determines where data is physically stored. If optional third-party services (Google OAuth, SendGrid) are configured, data may be transferred to those providers' servers in accordance with their respective privacy policies and data processing agreements. If Cloudflare tunnel is configured, encrypted request metadata may transit through Cloudflare's edge network.

12. Children's Privacy

PMO is not intended for use by individuals under the age of 16. We do not knowingly collect personal data from children. If you believe a child has provided personal data, contact the deploying organization's administrator for deletion.

13. Changes to This Policy

This privacy policy may be updated from time to time. Material changes will be communicated through the application or the deploying organization. The "Effective Date" at the top of this page indicates when the policy was last revised.

14. Contact

For privacy-related inquiries or to exercise your data rights, contact the administrator of the PMO instance you are using. For questions about this policy document, contact the PMO development team at the project's GitHub repository.
