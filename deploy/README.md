# deploy/ — Promise Model Online Production Deployment

This directory is the self-contained production deployment package. It contains everything needed to deploy to the VM, with no source code.

## Layout

```
deploy/
├── .env                  # Production config (no secrets)
├── docker-compose.yml    # Production compose (pulls images from Docker Hub)
├── ansible/
│   └── playbooks/
│       └── deploy-stack.yml   # Ansible playbook for deployment
├── scripts/
│   ├── init-db.sh        # MSSQL database initialization
│   └── umami-init.sh     # Umami analytics initialization
├── secrets/              # Populated by production bundle (blank in repo)
│   ├── auth_db_password.txt
│   ├── api_db_password.txt
│   ├── db_sa_password.txt
│   ├── cert_password.txt
│   ├── google_client_secret.txt
│   ├── sendgrid_api_key.txt
│   ├── umami_db_password.txt
│   ├── umami_admin_password.txt
│   └── cloudflare_tunnel_token.txt
└── keys/                 # Generated by Ansible on VM (blank in repo)
    ├── auth/             # Auth service certs (cert.pem, key.pem, cert.pfx)
    ├── bff/              # BFF service certs
    └── client/           # Client/nginx certs
```

## Deploying to Production

### Prerequisites

- **Ansible** installed on the host machine
- **rsync** installed on the host machine
- **SSH key** for the VM at `~/.ssh/pmo_vm_key`
- **Populated secrets** in `deploy/secrets/*.txt` (supplied via production bundle)

### Full Provision + Deploy (first time or clean rebuild)

```bash
ansible-playbook -i deploy/ansible/inventory/hosts.yml deploy/ansible/playbooks/site.yml
```

This runs `provision-vm.yml` then `deploy-stack.yml`:
1. Creates the QEMU/KVM VM from Ubuntu 24.04 cloud image
2. Installs Docker and configures the system
3. Syncs deploy files, generates certs, pulls images from Docker Hub
4. Starts the stack and waits for all health checks

### Deploy Only (VM already provisioned)

```bash
ansible-playbook -i deploy/ansible/inventory/hosts.yml deploy/ansible/playbooks/deploy-stack.yml
```

Both commands run from the repository root.

The playbook will:
- Sync the deploy directory to the VM
- Copy secret files from the local machine
- Generate self-signed certs in `keys/` (idempotent)
- Pull Docker images from `cherrytree811/promisemodelonline*`
- Start the stack and wait for all health checks

## Important Notes

- **No source code** is synced to the VM. Images come from Docker Hub.
- **No secrets** are in `.env` — they come from `secrets/*.txt` files.
- **Certs are not baked into images** — they're mounted as volumes from `keys/`.
- **Cert permissions** — set to `0644` in the playbook. The container's `app` user (UID 1654) differs from the VM user (UID 1000), so world-read is required for volume-mounted certs.
- **Passwords are exported via shell** before `docker compose up -d` (MSSQL and Umami don't support `_FILE`).
- **Model files** (`pmo_pm/`) are not included here — they're managed separately on the VM.

## Dev Certs

For local development, run from the repo root:
```
bash scripts/generate-dev-certs.sh
```
