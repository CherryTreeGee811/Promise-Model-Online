# deploy/ — Promise Model Online Production Deployment

Self-contained deployment package. No source code required.

## Prerequisites

- **Host machine** running Linux with QEMU/KVM
- `virsh`, `virt-install`, `qemu-img`, `xorrisofs`, `ansible`, `rsync` installed
- `libvirtd` service running (`sudo systemctl enable --now libvirtd`)
- 40GB+ free disk for the VM
- Internet access (downloads Ubuntu cloud image + Docker images)

## Quick Start

```bash
# 1. Populate the 4 required secrets (see Secrets section below)
nano secrets/google_client_secret.txt
nano secrets/sendgrid_api_key.txt
nano secrets/cloudflare_tunnel_token.txt
nano secrets/github_token.txt

# 2. Run the deploy script
bash deploy.sh
```

The script:
1. Checks prerequisites are installed
2. Validates the 4 required secrets exist
3. Generates an SSH key for the VM (if missing)
4. Runs `scripts/generate-secrets.sh` to create random passwords + self-signed certs
5. Calls Ansible to provision the VM and deploy the stack

## Secrets

### You Must Provide (4 files)

| File | Where to Get It |
|---|---|
| `secrets/google_client_secret.txt` | Google Cloud Console → OAuth 2.0 → Web client credentials |
| `secrets/sendgrid_api_key.txt` | SendGrid → Settings → API Keys |
| `secrets/cloudflare_tunnel_token.txt` | Cloudflare Zero Trust → Networks → Tunnels → your tunnel → token |
| `secrets/github_token.txt` | GitHub → Settings → Developer settings → Personal access tokens (scope: `issues:write`) |

### Auto-Generated by `generate-secrets.sh`

| File | Purpose |
|---|---|
| `secrets/auth_db_password.txt` | Auth database user password |
| `secrets/api_db_password.txt` | API database user password |
| `secrets/umami_db_password.txt` | Umami Postgres password |
| `secrets/umami_admin_password.txt` | Umami admin dashboard password |
| `secrets/cert_password.txt` | PFX certificate encryption password |
| `secrets/auth_registration_key.txt` | Registration key for new users |
| `secrets/db_sa_password.txt` | SQL Server SA password |

Plus all TLS certificates in `keys/` (client, auth, bff, proxy).

## What Ansible Does

The `ansible/playbooks/site.yml` playbook runs two stages:

### 1. `provision-vm.yml` — Creates the VM
- Downloads Ubuntu 24.04 cloud image
- Creates a QEMU/KVM VM (4 vCPU, 4GB RAM, 40GB disk)
- Injects SSH key, installs Docker, configures networking
- Waits for SSH to become available

### 2. `deploy-stack.yml` — Deploys the Stack
- Syncs `deploy/` files to the VM
- Copies secret files to VM
- Generates self-signed certificates (idempotent)
- Initializes Docker Swarm
- Creates Docker Swarm secrets from the secret files
- Pulls Docker images from DockerHub
- Deploys `docker-stack.yml` via `docker stack deploy`
- Waits for all services to stabilize

### 3. `update-stack.yml` — Rolling Update
- Syncs `deploy/` configs to the VM
- Pulls the latest `:latest` images from DockerHub
- Runs `docker stack deploy` to apply any spec changes
- **Force-updates** all 5 user services so Swarm re-resolves `:latest` digests and restarts with newly-pulled images
- Waits for all services to stabilize

### 4. `rollback-stack.yml` — Rollback to a Tagged Version
- Pins each service to a specific commit-SHA Docker tag via `docker service update --image`
- If a tag doesn't exist for a given service, that service is skipped with a warning (no crash)
- Supports per-service override via `service_override` dict
- Waits for all services to stabilize (respects `start-first` update config for zero-downtime)

## Routine Operations

### Update the stack (push new images to all services)

```bash
# Pulls latest :latest images, force-updates services to re-resolve digests
ansible-playbook -i ansible/inventory/hosts.yml ansible/playbooks/update-stack.yml
```

### Rollback a service to a previous SHA-tagged version

```bash
# Rollback ALL services to a specific commit SHA
ansible-playbook -i ansible/inventory/hosts.yml ansible/playbooks/rollback-stack.yml \
  -e 'sha=95aa2ce'

# Rollback only the client service (others keep current :latest)
ansible-playbook -i ansible/inventory/hosts.yml ansible/playbooks/rollback-stack.yml \
  -e 'sha=95aa2ce' \
  -e '{"service_override":{"promisemodelonline-client":"95aa2ce"}}'

# Rollback different services to different SHAs
ansible-playbook -i ansible/inventory/hosts.yml ansible/playbooks/rollback-stack.yml \
  -e 'sha=95aa2ce' \
  -e '{"service_override":{"promisemodelonline-client":"abc1234","promisemodelonline-api":"def5678"}}'
```

All services use `update_config.order: start-first` with health checks, so both update and rollback are **zero-downtime** — one replica updates at a time, new containers start before old ones stop.

### Teardown

```bash
ansible-playbook -i ansible/inventory/hosts.yml ansible/playbooks/destroy-stack.yml
```

## Architecture

```
Cloudflare Tunnel → VM:9000 → nginx-proxy (2 replicas)
                                ├── /api/* /hubs/*        → bff:8010 (2 replicas)
                                ├── /login /logout /oidc → bff:8010
                                ├── /connect/* /.well-known/* → auth:8060 (2 replicas)
                                ├── /account/* /signin-google  → auth:8060
                                ├── /umami/*              → umami:3000
                                └── /* (static)           → client:4000 (2 replicas)
```

│   ├── init-db.sh                # MSSQL initialization

├── secrets/                      # YOU POPULATE THESE
│   ├── google_client_secret.txt  # REQUIRED
│   ├── sendgrid_api_key.txt      # REQUIRED
│   ├── cloudflare_tunnel_token.txt # REQUIRED
│   └── github_token.txt          # REQUIRED
└── keys/                         # Auto-generated by generate-secrets.sh
    ├── client/                   # TLS certs for nginx
    ├── auth/                     # TLS certs + PFX for OpenIddict
    ├── bff/                      # TLS certs for BFF
    └── proxy/                    # TLS certs for proxy
